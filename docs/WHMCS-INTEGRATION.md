# WHMCS配合事项

## 已有能力

据当前说明，WHMCS已经可以：

- 选择/克隆模板。
- 设置IP等Cloud-Init网络参数。
- 设置SSH相关参数。
- 启动VM并执行现有开通流程。

模板v2不会取代这些能力。

## 唯一明确缺项：QoS

WHMCS需要在克隆完成、最终磁盘卷名确定后，通过Proxmox API修改最终VM的所有真实数据盘。不要给来宾系统下发QoS文件。

本项目的默认档位会下发带宽、IOPS和IOPS Burst时间。按当前设计不增加`bps_rd_max_length`和`bps_wr_max_length`；未设置时采用PVE/QEMU的默认带宽Burst窗口。

推荐顺序：

1. 克隆模板并等待PVE任务成功。
2. 设置CPU、内存、磁盘大小和Cloud-Init参数。
3. 获取最终VM配置，枚举`scsi/virtio/sata`数据盘，排除`media=cdrom`。
4. 根据套餐映射写入每块盘的QoS。
5. 再次读取VM配置，逐字段核对期望值。
6. 任一真实数据盘缺少限制时，不启动VM、不标记订单成功。
7. 验证通过后启动VM并继续现有Cloud-Init流程。

## 套餐映射

QoS值只能由WHMCS服务端根据产品ID选择。客户表单不得直接提交任意Proxmox磁盘参数。

模板默认值可作为Standard安全兜底。Basic套餐向下覆盖，Premium套餐向上覆盖。升级、降级、添加或删除数据盘时必须重新计算并回读验证。

## 多盘规则

如果商品承诺“整台VPS 300 MB/s”，最简单可靠的方式是只提供一块可扩容系统盘。若提供多块盘，必须把整机总额度分摊；不能让每块盘都继承完整300 MB/s。

## 失败处理

- QoS API调用失败：订单进入待处理/重试，不得静默启动无限速VM。
- 克隆成功但后续失败：保留任务日志和VMID，按幂等规则重试或安全回滚。
- 日志记录产品ID、VMID、磁盘键和QoS档位，但不记录明文密码、私钥或完整API Token。
- 定时审计所有运行VM，告警没有带宽或IOPS限制的真实数据盘。
